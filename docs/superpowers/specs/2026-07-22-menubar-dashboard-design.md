# sidedash — 메뉴바 개인 대시보드 설계

## 배경 및 목적

debrief, reentry-cli, resume-ym 등 개인 사이드 프로젝트용 CLI 도구를 여러 개 만들었지만,
매번 실행 명령어와 인자를 기억해내야 해서 재진입 비용이 든다. 이 도구들을 하나로 합치는 대신,
macOS 메뉴바에 상주하면서 버튼 클릭으로 각 도구를 실행할 수 있는 개인용 대시보드 앱을 만든다.

배포/출시를 목표로 하지 않는 개인 전용 도구이므로 코드사이닝, 노터라이제이션, 자동 업데이트,
App Store 배포 등은 스코프에서 제외한다.

## 아키텍처

- **Electron 앱**, Dock 아이콘 없이 메뉴바에만 상주. 트레이 아이콘 클릭 시 팝업 형태의
  드롭다운을 띄우는 데는 `menubar` npm 패키지를 사용한다 (트레이 팝업 위치 계산, 바깥 클릭 시
  닫기 등을 대신 처리해주는 라이브러리).
- **데이터 레이어는 새로 만들지 않는다.** reentry-cli가 이미 `~/.pj/registry.json`에 프로젝트
  레지스트리를 저장하고, `src/registry.js`(등록/조회/삭제)와 `src/scanner.js`(git 브랜치/최근
  커밋/미커밋 변경 여부/`package.json` scripts/TODO 스캔)로 로직을 분리해두었다. sidedash는 이
  두 모듈을 그대로 import해서 재사용한다. 즉 터미널에서 `pj add`로 등록하든 sidedash 앱에서
  등록하든 동일한 레지스트리를 공유한다.
- reentry-cli의 기존 CLI(`pj`)와 `pj dashboard`(정적 HTML 생성)는 그대로 유지하고 건드리지
  않는다. sidedash는 별도 저장소/프로세스로 존재하는 새 프로젝트다.

## 컴포넌트

### 1. 메인 드롭다운 (트레이 팝업)

- 상단: "내 프로젝트 (N)" 라벨 + ＋ 버튼. ＋ 클릭 시 네이티브 폴더 선택 다이얼로그
  (`dialog.showOpenDialog`)를 열고, 선택한 폴더를 `registry.js`의 `add()`로 등록한다.
- 카드 목록: 레지스트리에 등록된 프로젝트마다 카드 하나.
  - 기본 표시: 이름 / 상태 한 줄 (브랜치 + 마지막 커밋 시각, 또는 경로가 없으면 "경로를 찾을
    수 없음"을 빨간 텍스트로) / 우측 상단 ✕ 삭제 버튼(`registry.js`의 `remove()`).
  - 카드를 클릭하면 상세정보가 펼쳐진다: TODO/FIXME 개수, `package.json` scripts 목록 등
    (`scanner.js`에 이미 있는 로직 재사용). 다시 클릭하면 접힌다.
- **특수 액션 버튼은 이름이 아니라 파일 존재 여부로 자동 감지한다:**
  - 프로젝트 루트에 `run.sh` 파일이 있으면 → "파이프라인 실행" 버튼 표시 (debrief 해당)
  - `package.json`의 `scripts`에 `pdf` 키가 있으면 → "PDF 생성" 버튼 표시 (resume-ym 해당)
  - 둘 다 없으면 액션 버튼 없이 상태 카드로만 표시 (reentry-cli 등 나머지 전부)
  - **단, 이 자동 감지는 "버튼이 나타나는지"에만 적용된다.** 버튼을 눌렀을 때 실제로 어떤
    인자를 넘기고 완료 후 무엇을 여는지(아래 "액션 실행 및 로그 창" 참고)는 지금 debrief와
    resume-ym 두 프로젝트에 한정된 동작으로 하드코딩한다. 나중에 `run.sh`나 `pdf` 스크립트를
    가진 제3의 프로젝트를 등록하면, 버튼은 자동으로 나타나지만 debrief/resume-ym과 동일한
    동작(예: "다른 등록된 프로젝트 경로 전체를 인자로 받음")이 그대로 적용된다 — 이게 그
    프로젝트에 맞지 않으면 코드를 추가로 고쳐야 한다. (스코프 밖 섹션 참고)
- 프로젝트가 실행 중인 동안 해당 카드의 액션 버튼은 비활성화되고 스피너로 바뀐다 (중복 실행
  방지).
- 하단: 구분선 + "종료" (앱 종료).

### 2. 액션 실행 및 로그 창

- 액션 버튼 클릭 시 별도의 작은 `BrowserWindow`(로그 창)를 띄운다.
- 명령어는 `child_process.spawn`으로 실행하고, stdout/stderr를 IPC를 통해 실시간으로 로그
  창에 스트리밍한다 (터미널처럼 흐르는 출력).
- **debrief 실행**: 실행 대상 저장소 목록을 별도로 설정하지 않는다. 레지스트리에 등록된
  프로젝트 중 debrief 자신을 제외한 나머지 전체 경로를 인자로 넘겨
  `./run.sh <path1> <path2> ...`를 debrief 프로젝트 경로에서 실행한다.
- **resume-ym 실행**: 해당 프로젝트 경로에서 `npm run pdf`를 실행한다.
- **완료 시:**
  - 성공/실패 여부를 로그 창 하단에 표시한다.
  - 성공한 경우, 결과물을 바로 여는 버튼을 추가로 보여준다.
    - debrief 완료 → "노트 열기" (notes 폴더를 Finder로 연다)
    - resume-ym 완료 → "PDF 폴더 열기" (`pdf-output` 폴더를 Finder로 연다)
  - 실패한 경우(0이 아닌 종료 코드), 로그 창은 자동으로 닫히지 않고 에러 출력이 그대로
    남아있어 원인을 확인할 수 있다.

## 에러 처리

- 레지스트리에 등록된 경로가 실제로 존재하지 않으면 카드에 "경로를 찾을 수 없음"을 빨간
  텍스트로 표시하고, 액션 버튼은 노출하지 않는다.
- 명령어 실행이 0이 아닌 종료 코드로 끝나면 로그 창에 실패로 표시하되, sidedash 앱 자체는
  계속 정상 동작한다 (한 프로젝트의 실행 실패가 앱 전체에 영향을 주지 않는다).
- **PATH 상속 문제:** Finder/Dock으로 실행되는 GUI 앱은 터미널과 달리 `~/.zshrc` 등에서
  설정한 PATH(nvm으로 관리하는 node/npm 등)를 상속받지 못하는 경우가 흔하다. `npm run pdf`나
  `python3` 같은 명령어를 `child_process.spawn`으로 직접 실행하면 터미널에서는 되던 게 앱에서
  "command not found"로 실패할 수 있다. 이를 막기 위해 spawn 시 로그인 셸을 통해 실행한다
  (예: `spawn("/bin/zsh", ["-lc", "npm run pdf"], { cwd })`)— 사용자의 셸 설정을 그대로
  상속받아 PATH 문제를 피한다.

## 테스트

- reentry-cli의 기존 `registry.js`/`scanner.js` 관련 vitest 테스트는 그대로 유지하고
  수정하지 않는다.
- sidedash에서 새로 추가하는 순수 로직(예: "이 프로젝트 폴더가 어떤 액션 버튼을 가져야
  하는지 판별하는 함수", "debrief 실행 인자를 조립하는 함수")은 vitest 유닛 테스트로 커버한다.
- Electron UI 자체(트레이 팝업, 로그 창 렌더링)는 자동화 테스트 없이 직접 실행하며 수동으로
  확인한다. 개인용 도구 규모에서 E2E 테스트까지는 과도하다고 판단.

## 스코프 밖 (지금은 하지 않음)

- 코드사이닝/노터라이제이션/자동 업데이트/App Store 배포
- 정렬 토글(최근순/이름순) — 프로젝트 수가 늘어나면 나중에 추가 가능
- 로그 히스토리 저장(창을 닫아도 마지막 로그 다시 보기) — 필요해지면 나중에 추가
- 등록된 프로젝트 중 debrief/resume-ym 외에 다른 도구용 자동 액션 감지 규칙 추가 — 지금은
  `run.sh`, `package.json`의 `pdf` 스크립트 두 가지 관례만 지원
